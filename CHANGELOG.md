# Changelog

## [Unreleased]

### Changed
- Licence: `MIT OR Apache-2.0` → `LicenseRef-Proprietary`

- **Breaking (0.2.0)**: the stores serve keys through `alice_crypto::KeyProvider` (re-exported with `Key`, `KeyGeneration`, `KeyProviderError`). `KeyVault`, `VaultError` and `DataKey` are removed. `current` / `by_generation` replace `current` / `by_id`; generation 0 is never a key (`UnknownGeneration(0)`); errors carry fixed reasons, not text from the operating system or a foreign store. `MemoryVault::generate` is now `rotate`, `MemoryVault::insert` refuses generation 0, and a retired generation is `Irrecoverable` instead of unknown. `ffi::ForeignVaultAdapter` implements `KeyProvider`: a key that is not 32 bytes, or a current generation of 0, from the foreign side is `Irrecoverable` (was `InvalidKeyLength`). The UniFFI interface (`ForeignKeyVault`, `GenerationKey`, `ForeignVaultError`) is unchanged
- Tests: the macOS Keychain tests clean up after a killed run through per-run manifests of the services they create (written before the service is used); the sweep looks each listed service up by name and no longer lists the keychain with a search that has no service, which can miss items another process added just before. `macos_keychain` runs 18 tests
- CI: `scripts/with_keyring.sh` runs gnome-keyring in the foreground as its child, with the daemon's output kept in a log, and starts the command only after `org.freedesktop.secrets` is owned by that daemon. The private bus has no activatable services, so a daemon that exits is not replaced by a fresh, locked one. If the daemon is gone or no longer owns the name when the command ends, the run fails and prints the log. `scripts/test_with_keyring.py` (CI scripts job and preflight) checks this against a real gnome-keyring, and checks that copies of the script with either safeguard removed let the failure through
- CI: the coverage job runs the tests against gnome-keyring in a private D-Bus session, as the test job does, and through `scripts/run_tests.sh` with each binary's minimum count (the Linux store's 13 tests included). It is no longer `continue-on-error`, so a store whose tests fail under coverage fails the job
- CI: package integrity resolves `alice-*` from a local registry built from the pinned commit (`scripts/alice_local_registry.py`, the same script as in the other ALICE crates) instead of crates.io, where `alice-crypto` 0.6 is not published; the packaged lock must take every `alice-*` crate from that registry with a matching checksum, and the extracted `.crate` is built on its own with `--locked`
- Dependencies: `alice-crypto` 0.6 (git, full commit), `security-framework` and `core-foundation` on macOS; `getrandom` is no longer a direct dependency
- License: the crate is now proprietary (`LicenseRef-Proprietary`, all rights reserved, see `LICENSE`), and so is the binding generator in `tools/uniffi-bindgen`. `LICENSE-MIT` and `LICENSE-APACHE` are removed; commits made before this change stay under MIT OR Apache-2.0, the licence they were made under. `deny.toml` no longer checks the licence of the repository's own unpublished crates (`private = { ignore = true }`); dependencies are checked against the same allow list as before.
- `.github/dependabot.yml` を削除した
- Unsafe code policy: the crate no longer forbids `unsafe` everywhere. It denies it everywhere except one private module, `src/sys/`, which holds the operating system calls (each `unsafe` block with a `SAFETY:` note). `scripts/unsafe_scope_check.py` (CI and preflight) fails on any `unsafe` outside it. Reading a secret on a Windows console needs these calls; the desktop key stores will use the same module
- CI: the fuzz jobs check that `fuzz/Cargo.lock` is current (`cargo metadata --locked`) before the build; `cargo fuzz` has no `--locked` and re-resolved a stale lock silently

### Added

- `desktop::LinuxSecretServiceStore`: keys as Secret Service items (default collection, attributes `keystore-service` / `keystore-generation`, encrypted transfer of the secrets) through `secret-service` 5.2, with a marker item per issued generation; duplicates left by racing creators resolve to the item with the earliest service-set `Created`, then the lowest object path, a creator returns its own key only when its item was chosen, and `duplicate_count` reports the rest (also logged with `log`); no session bus, a locked keyring or no default collection is `Unavailable`. Tested against gnome-keyring in a private D-Bus bus on Linux (`scripts/with_keyring.sh`; CI requires the 14 tests there). `tests/desktop_gaps.rs` is removed: no desktop store fails fast any more
- `scripts/advisory_holds.toml` + `scripts/advisory_hold_guard.py` (the same guard as in the other ALICE products): RUSTSEC-2026-0370 / 0371 / 0372 (zvariant / zbus_names / zvariant_derive unmaintained, from zbus 5.19 through secret-service 5.2) are ignored in `deny.toml` only while the held version, its direct dependents and the expiry (2027-01-31) match `Cargo.lock`
- `desktop::MacosKeychainStore`: keys in the macOS login keychain, one generic password item per generation (`gen-<n>` under the caller's service name), created with `SecItemAdd` so concurrent first use and concurrent rotation each end with one item per generation; `current` creates generation 1 on first use, `rotate` adds the next; for every issued generation a create-only marker item `issued-<n>` is written after the key item, so a number is never issued twice: a removed key at or below the highest issued generation is `Irrecoverable`, `current` reports a removed newest key as `Irrecoverable` instead of falling back to an older one (`rotate` continues above it), and a key item found without its marker gets one when read. Limit: removing both the newest key item and its marker erases the record and frees that number. An item that is not 32 bytes is `Irrecoverable`. Tested against the real login keychain on macOS (CI requires the 10 tests there). - `desktop::WindowsDpapiStore`: keys as DPAPI-sealed files of the current user, one `gen-<n>.dpapi` per generation in `%LOCALAPPDATA%\<service>` (or `in_dir`), bound to the directory's name, written under a temporary name and hard-linked so a generation appears whole and concurrent creation has one winner, with an `issued-<n>` marker file per issued generation; same model as the macOS store, a file that does not open is `Irrecoverable`; `new` takes only a plain directory name. The DPAPI calls are in `src/sys/` with `SAFETY:` notes. Tested against the real DPAPI on Windows (CI requires the 16 tests there)
- Tests: the prompt keeps reading lines when the terminal was left with `IGNCR` or `INLCR` (pseudo-terminal tests, mode restored after), dropping the UTF-16 decoder zeroes a waiting half and bytes not taken (checked in the freed block by a test-only allocator in `src/sys/`), and on Linux `fs::exchange` refuses two paths on different file systems with `EXDEV` without moving anything. The prompt docs state that a Windows console delivers Ctrl-Z as the byte `0x1A`, so `Closed` is not returned there
- `fs::exchange`: swap two paths (any two entries: directories, files, symbolic links, which are not followed; the same path twice is a no-op; different file systems fail with `EXDEV`) in one atomic step (Linux `renameat2` `RENAME_EXCHANGE`, Apple `renameatx_np` `RENAME_SWAP`, through `rustix`'s safe API), for replacing a directory of keys and data all or nothing. Other platforms return `ExchangeError::Unsupported` without changing anything, so the caller picks a fallback it can recover from
- `prompt::read_secret` / `read_secret_from`: read a secret from a terminal with echo off (unix: termios through `rustix`, Windows: console mode, read as UTF-16 with `ReadConsoleW` and converted to UTF-8). While reading, the terminal is in line mode (unix: `ICANON` + `ICRNL`, `INLCR` / `IGNCR` cleared; Windows: line + processed input) and a line feed or a carriage return ends the line. The previous mode is restored when the call returns or unwinds; it is not restored when the process ends without unwinding (default `SIGINT`, `panic = "abort"`, `process::exit`), which the docs describe with the way to recover. A non-terminal input is refused before anything is written (`PromptError::NotATerminal`); an empty line, a line longer than `prompt::MAX_SECRET_LEN` (512 bytes), input that ends early and non-UTF-8 input (on Windows also an unpaired surrogate) are separate errors. The line is read into one fixed heap buffer that is zeroed before the call returns, and returned in zeroizing memory
- Data keys by generation through `alice_crypto::KeyProvider` (re-exported with `Key`, zeroed on drop and not printed, and `KeyProviderError`: `UnknownGeneration` / `Unavailable` / `Irrecoverable`)
- `MemoryVault`: keys in memory only, for tests and ephemeral data; `rotate` adds the next generation above every generation ever stored, and a retired generation is `Irrecoverable` (its number is not issued again)
- `uniffi` feature: `ffi::ForeignKeyVault` callback interface and `ffi::ForeignVaultAdapter` (a `KeyProvider`: accepts only 32-byte keys and generations of at least 1, keeps the error kind with fixed reasons)
- `desktop::{MacosKeychainVault, WindowsDpapiVault, LinuxSecretServiceVault}`: not implemented, every call fails fast
- `apple/` Swift package: `SecureEnclaveVault`, `MasterVault`, `KeychainVault`
- CI: fmt / clippy (pedantic, both feature sets, on Linux and Windows) / test on Linux, macOS, Windows through `scripts/run_tests.sh` (each test binary has a minimum count) / doc / Apple (`scripts/apple_check.sh`: iOS and iOS Simulator libraries, the generated Swift binding, the Swift package for device and Simulator, and the README's conformance snippet typechecked) / security & hygiene (audit, deny, unused dependencies, stub guard, package integrity, coverage) / fuzz (3 targets) / public text / line endings; `scripts/preflight.sh` generated from the workflows
- `tools/uniffi-bindgen`: the binding generator as a separate tool crate, so that its build-time dependencies (askama 0.12 -> basic-toml, unmaintained) stay out of the library
- `KeyProviderError::Irrecoverable` / `ForeignVaultError::Irrecoverable` / Swift `KeystoreError.irrecoverable`: a key that cannot be recovered (wrapping key gone, wrapped blob does not open) is no longer reported as the retryable `Unavailable`
- `MasterVault` stores the secret in numbered slots and writes the new slot before removing the old one (a failure while storing keeps the previous secret)
- `apple/Tests`: slot rules and error classification (`swift test`)
- `scripts/audit_ignore_guard.py` (security-audit の audit job): RUSTSEC-2026-0374 の ignore は basic-toml が Cargo.lock にあり、どの feature でも build されない間だけ有効 build される (reachable) か lock から消えた (stale) ら fail、比較できない時も fail 試験は小さな crate 9 通り (iOS だけで到達、feature の後ろで到達、cargo tree の失敗、Cargo.toml と食い違う lock、空の lock を含む) cargo tree は --locked で走り、lock を解決し直さない
- Apple: every Keychain call goes through `SystemKeychain` with `kSecUseDataProtectionKeychain` (on macOS this needs a signed, entitled app; `KeychainVault` items move from the file-based keychain to the data-protection keychain there); the three vaults are tested through an in-memory keychain with injected faults, and the dictionaries reaching the Security functions are recorded in a test

### Fixed

- macOS Keychain store: calls into the Security framework from several threads of one process could deadlock inside the framework (seen in about 1 of 10 runs of the concurrent tests on CI, every thread waiting on the framework's own mutexes). Every call of the store, including releasing the returned objects, now runs under one process-wide lock
